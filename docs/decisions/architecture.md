# 專案架構 (Project Architecture)

本文件描述了 `resume` 專案的軟體架構、模組職責以及組件間的依賴關係。

## 架構概覽

本專案遵循 Flutter 的分層架構設計，並嚴格遵守 **UI → Provider → Model** 的單向依賴原則，確保代碼的可測試性與解耦。

## 核心層級職責

### 1. 展示層 (Presentation Layer)
*   **職責**: 處理 UI 構建、佈局響應式設計以及捕捉使用者操作。
*   **HomeScreen**: 應用程式的主框架，管理導航列與整體佈局。
*   **Sections**: 將履歷拆分為多個獨立 Widget（如 `HeroSection`, `SkillsSection`），提高程式碼可讀性與維護性。

### 2. 業務邏輯層 (Business Logic Layer)
*   **職責**: 封裝應用程式狀態與業務邏輯，並透過 `notifyListeners()` 通知 UI 更新。
*   **LanguageProvider**: 封裝多國語言切換邏輯，與 `easy_localization` 協同工作。

### 3. 數據層 (Data Layer)
*   **職責**: 負責資料結構的定義與原始資料（JSON）的解析。
*   **ResumeModel**: 提供強型別的資料存取，並包含簡單的資料過濾與格式化邏輯（如：按日期排序工作經歷）。

## 依賴規則
*   **單向依賴**: UI 層可以感知 Provider 層，Provider 層可以感知 Model 層。反之則不允許，以避免循環依賴。
*   **解耦設計**: UI 組件應儘量保持「展示型 (Presentational)」，不應直接包含複雜的業務邏輯或直接存儲數據。
