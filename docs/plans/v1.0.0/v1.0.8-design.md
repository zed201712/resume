# v1.0.8 設計：網址參數指定顯示語言

## 目標
投遞履歷時附上帶語言參數的連結（例如 `?lang=jp`），對方打開即看到該語言版本。

網址只作為**入口連結**：頁面上切換語言時不回寫網址。

## 顯示語言的決定順序
1. 網址 `?lang=` 有效 → 使用它（新增）
2. 曾在頁面切換過 → 使用已存的選擇
3. 瀏覽器語言
4. 中文（fallback）

## 參數對應（不分大小寫）

| `?lang=` | 語言 |
|---|---|
| `en` | 英文 `en` |
| `jp`、`ja` | 日文 `ja` |
| `ch`、`zh` | 中文 `zh` |
| 其他值或未帶參數 | 忽略，依原規則 |

## 實作

### 1. 對應規則 `lib/utils/locale_from_query.dart`
純函式 `Locale? localeFromQuery(String? lang)`，只負責上表的轉換。

### 2. 套用 `lib/main.dart`
- `main()` 讀 `Uri.base.queryParameters['lang']`，交給 `localeFromQuery`，結果傳給 `ResumeApp(urlLocale: ...)`。
- `ResumeApp` 在第一個 frame 後呼叫一次 `context.setLocale(urlLocale)`。

**為什麼不用 `EasyLocalization(startLocale:)`**：easy_localization 3.0.8 的 `EasyLocalizationController` 在已有存過的語言時會忽略 `startLocale`（見 `easy_localization_controller.dart` 建構子），曾切換過語言的訪客點連結時仍會看到舊語言。改用公開的 `setLocale` 可避免依賴套件內部的 SharedPreferences key。

`setLocale` 會同時存下該語言，因此訪客之後不帶參數再開，仍是同一語言。

非 Web 平台的 `Uri.base` 沒有 query，自然忽略。
